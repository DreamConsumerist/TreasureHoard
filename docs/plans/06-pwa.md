# Plan: Installable app (PWA) for iPhone

**Status:** approved 2026-11-25. Icon: a bare placeholder; the app's visual design is its own project later. Sliding session: yes.

## Context

The site already has a phone layout (bottom tab bar, quick-add sheet, card lists), but on an iPhone it only runs as a Safari tab. This step makes it installable: Share → **Add to Home Screen** gives it its own icon, and it opens full-screen with no Safari bars, like an app.

This was part of Step 7 (Polish). It's pulled forward because the phone is where recurring bills get confirmed and items get added. **The wishlist (old Step 6) is deferred**, and so are **push notifications**. Both stay in the build order for later.

**Done when:**
- On your iPhone, Add to Home Screen gives a TreasureHoard icon. Opening it shows the app full-screen, with the status bar and the home indicator clear of the content.
- The app opens fast, even on a weak connection: its code is stored on the phone.
- With no connection, it says so plainly instead of showing a Safari error page.
- After a deploy, the installed app offers **Reload for the new version** rather than reloading itself mid-entry.
- Your financial data is **never** stored by the service worker. Every API request still goes to the server.

**Not in this step:**
- Working with data offline (entering transactions without a connection and syncing later).
- Push notifications.
- The wishlist.

## 1. What a PWA is made of

| Piece | What it is | Here |
|---|---|---|
| **Web app manifest** | A small JSON file describing the app: name, icons, colours, and `display: standalone` (open without browser bars) | Generated at build time by `vite-plugin-pwa` |
| **Icons** | PNGs at the sizes phones want. iOS uses a 180×180 `apple-touch-icon` | Generated from one source SVG by `@vite-pwa/assets-generator` |
| **Service worker** | A script the browser installs and runs between the app and the network. It can answer requests from a local cache | Generated by `vite-plugin-pwa` (using Google's **Workbox** library). It caches only the app's own files |

**New libraries (dev dependencies only; nothing new runs on the server):**
- **`vite-plugin-pwa`** (2.x, supports Vite 8): already chosen in ARCHITECTURE.md. It writes the manifest and service worker during `npm run build`, and gives React a small hook for "a new version is ready".
- **`@vite-pwa/assets-generator`**: turns one SVG into every icon size. Run once by a script, and the PNGs are committed.

## 2. The icon (yours to judge)

The current favicon is **Vite's default logo**, left over from the project template. The app needs its own icon.

**Default I'll use:** a simple, bold glyph drawn as an SVG: a gold coin stack or a small chest on the app's near-black (`#18181b`). Home-screen icons are small, so detail doesn't survive. The same SVG becomes the favicon. If you'd rather supply your own image (at least 512×512, square), drop it in and I'll regenerate the sizes.

## 3. Service worker rules

The most important rule: **the service worker never caches API responses.**

- **Cached:** the built app (`index.html`, JS, CSS, icons, fonts). It's precached at install, and a new deploy replaces it.
- **Never cached:** `/api/*`, `/.netlify/*` (functions), and the login. These are excluded from the page-navigation fallback, and no runtime caching rule touches them. Balances and prices are always live.
- **Product photos** (TCGplayer and PriceCharting images) are left to Safari's normal HTTP cache. A service-worker cache for other sites' images can hit iOS storage limits for little gain.
- **Updates use "prompt" mode.** When a new deploy is detected, a small bar says **New version available · Reload**.
  - The alternative, "autoUpdate", reloads on its own. That could throw away a half-filled form.
- **In local development the service worker is off** (the plugin's default). A cached app would only get in the way of `npm run dev`.

## 4. iPhone-specific fixes

- **`viewport-fit=cover`** in `index.html`. Without it, iOS reports the safe-area insets as zero, so the bottom tab bar's existing `env(safe-area-inset-bottom)` padding does nothing. In full-screen mode the home indicator would then sit on top of the tabs.
- **Top safe area:** padding for the status bar, so the clock and battery don't overlap page headers in full-screen mode.
- **Status bar style:** `apple-mobile-web-app-status-bar-style`, so its text stays readable in light and dark mode.
- **No zoom when tapping into a field:** iOS zooms the page when an input's text is smaller than 16px. The main `.input` class is already 16px, but the split-grid memo field uses 14px. It'll be 16px on phones.
- **Offline notice:** a slim bar ("You're offline. Changes can't be saved until you're back online."), driven by the browser's `online`/`offline` events. API errors while offline then make sense.

## 5. Staying logged in

Sessions last 30 days from login. After that you're sent to the login screen, even if you used the app yesterday.

**Proposed: a sliding session.** When a request arrives with a session older than 7 days, the API re-issues the cookie for another 30 days. Used weekly, you'd never be logged out; left alone for 30 days, you would be.
- **The security trade-off is small:** a stolen cookie could be kept alive by use. That's already true for its first 30 days, and it's still only one device's cookie.
- **Note for iPhone:** an installed app keeps its cookies separate from Safari, so you'll log in once inside the installed app.

## 7. Verification

- `npm test`, `npm run build`, `npm run lint`. The build output lists the manifest and `sw.js`.
- **Locally:** `npm run build`, then `npx vite preview`. Desktop Chrome's DevTools → Application shows the manifest, icons and an active service worker, and confirms `/api` requests go to the network.
- **On your iPhone (this needs HTTPS, so it can't be done against your local dev server):**
  1. Push to `dev` (a free branch deploy) and open its URL in Safari.
  2. Share → Add to Home Screen, then open it from the icon. It should be full-screen, with the tab bar clear of the home indicator. Log in once.
  3. Turn on Airplane Mode and open the app: it should load, with the offline bar showing. Turn Airplane Mode off and it works normally.
  4. After the next deploy, the app shows the Reload bar.
- **Cost:** none. Static files only; no functions or database use.
